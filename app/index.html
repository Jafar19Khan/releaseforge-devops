01 / DELIVERY FLOW

From commit to confidence.

Every stage has a clear purpose. A release is not complete just because the image built — the running service must answer.

01⌘

Validate the source

Check required files and page markers before spending time on packaging or deployment.

Fail early
02▧

Build the artifact

Package the static experience into a small Nginx container with a predictable runtime.

Repeatable image
03⇧

Deploy deliberately

Use a named service and explicit port mapping instead of broad host-wide cleanup commands.

Scoped change
04✓

Verify the release

Check the health endpoint and expected page content after the container starts.

Evidence-led
02 / ENGINEERING PRINCIPLES

Small surface area.
Clear operational signals.

The application is deliberately simple. That keeps attention on delivery controls, container health, and the path from a source change to a verified response.

Make the result easy to trust.

Operational checks stay close to the release so a green build is backed by a real HTTP response.

Verify what is actually running.

Run the same simple checks locally or in CI to catch missing assets, startup issues, and incorrect routing before calling the release complete.
